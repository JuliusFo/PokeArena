# PokeArena — Game Specification (v1)

A persistent Pokemon collecting and battling game played through Twitch chat.
The bot runs as a WPF desktop application on the streamer's machine; viewers
play entirely via chat commands. A static Blazor website shows the leaderboard,
trainer pages and battle logs.

Status: concept frozen 2026-09-03. Open points are marked **OPEN** and
collected in the last section. Conventions: code and documentation in English,
all chat output and UI text in German.

---

## 1. Core concepts

- **Trainer** — a viewer, identified permanently by their **Twitch user id**
  (never by display name; names can change). The current display name is
  stored alongside and refreshed when seen.
- **Species (Art)** — one of the 151 Gen-1 Pokemon, defined in the base data
  (`data/pokemon.json`). Each species has its Gen-1 type(s): **one or two**.
- **Specimen (Exemplar)** — one owned instance of a species. Duplicates are
  allowed; every catch creates a new specimen. Exactly one specimen per
  trainer is flagged as the **starter**.
- **Achievement (AV)** — unlocked at thresholds of *distinct species owned*
  (15, 25, 40, 60, 70, 80, 90, 100, 105, 110, 115, 130, 135, 140, 145, 150,
  151). Once unlocked, an achievement is **never lost**, even if the distinct
  count later drops below the threshold. Each achievement unlocks the
  corresponding NPC.
- **Badge (Orden)** — earned by the first win against an NPC (§7); permanent
  like an achievement.
- **Tokens** — a per-trainer balance earned by the first win against each NPC
  (§7), to be redeemed with the streamer for rewards later (not in v1 yet,
  backlog).

## 2. Base data

`data/pokemon.json`, one entry per species. Generated by
`tools/GeneratePokemonData.cs` from PokeAPI with the **official Generation-I
values** (ADR-0005); `seltenheit` comes from a rule in that script (list
accepted 2026-10-11). The catch-rate column from earlier drafts is
dropped because catching is deterministic (see §4).

| Field       | Meaning                                                    |
|-------------|------------------------------------------------------------|
| `id`        | 1–151, national dex number                                 |
| `name`      | official German name (display)                             |
| `slug`      | URL/command-safe name, lowercase; `nidoran-m`/`nidoran-w` for the two Nidoran |
| `hp`        | base HP                                                    |
| `atk`       | base attack                                                |
| `def`       | base defense                                               |
| `spez`      | Gen-1 Special: special attack **and** special defense (§5) |
| `typen`     | one or two types, Gen-1 order (see `data/typen.json`)      |
| `seltenheit`| 1 = common, 2 = rare, 3 = legendary (boss draw weighting)  |

`data/typen.json` holds the Gen-1 type chart (15 types). House rule: there is
no immunity — every `0×` entry of the original chart is replaced by **0.25**.
Deliberate Gen-1 quirks kept (differ from modern charts): Poison and Bug are
super effective against each other, Ice is neutral against Fire, Ghost gets
0.25 (was 0) against Psychic.

Dual types (ADR-0005): against a defender with two types the factors of both
are **multiplied** (range 0.0625–4). An attacker with two types attacks with
the type that has the **higher** factor against the defender.

## 3. Registration

- `!registrieren <Starter>` — one-time, irrevocable choice of one of five
  starters: **Bisasam, Schiggy, Glumanda, Pikachu, Evoli**.
- Creates the trainer and their starter specimen.
- Any game command from an unregistered user gets a hint pointing to
  `!registrieren` (no auto-registration).
- Only the first word after the command counts; name or slug, any case.
- Replies (final wording: [chat-texts.md](chat-texts.md)):
  - success: „@Name, willkommen bei PokeArena! Dein Starter ist Pikachu. Mit
    !boss kämpfst du mit, sobald ein Boss erscheint."
  - already registered: „@Name, du bist schon dabei – dein Starter ist
    Pikachu."
  - missing or invalid starter: „@Name, wähle deinen Starter: Bisasam,
    Schiggy, Glumanda, Pikachu oder Evoli – zum Beispiel: !registrieren
    Pikachu"
  - unregistered user, game command: „@Name, du bist noch nicht dabei. Melde
    dich an, zum Beispiel mit !registrieren Pikachu."
- Everyone may play; no follower/sub gate. One configured channel only.

## 4. Boss encounter (`!boss`)

Trigger and lobby:

1. A registered user types `!boss` while no encounter runs and the global
   cooldown has elapsed → a lobby opens with a countdown
   (`BossCountdownSeconds`, default 120, was 60 until 1.0.3 and 30 until
   1.0.1; a whole number of minutes is announced as „2 Minuten“). Announcement
   is generic („Ein wilder Boss nähert sich!") — the boss is not yet determined.
2. During the countdown every registered user (including the initiator,
   automatically) joins via `!boss`. Joining twice is a no-op. A trainer who
   joins **for the first time** with at most `BossVerlaengerungSeconds`
   (default 10) left extends the countdown by that much (streamer request
   2026-11-08), so a last-second `!boss` still makes it. Joining again never
   extends; the extension is not announced in chat (one message per join
   would flood it). The total is bounded by the number of trainers.
3. If fewer than `BossMinTeilnehmer` (default 2) joined when the countdown
   ends: message „Der Boss entkommt – es haben sich zu wenige Trainer
   getraut. Mindestens 2 müssen mit !boss mitmachen.", short retry
   cooldown (`BossFehlschlagCooldownMinutes`, default 2), no full cooldown.

Boss draw (after the lobby closes, so participant count is known):

- Tier probabilities grow with participant count `N` and are capped:
  `p(legendär) = min(Cap3, Basis3 + ProSpieler3 × N)` (defaults 1 % + 1 %/player, cap 20 %),
  `p(selten)   = min(Cap2, Basis2 + ProSpieler2 × N)` (defaults 10 % + 2 %/player, cap 40 %),
  remainder → common. Within a tier the species is drawn uniformly.
- Boss HP = base HP × `HPFaktor` × `BossHPProSpieler` × `N` (default 1.5,
  was 1.8 until 1.0.0).
  Other stats are the base values. Together with the target count below this
  keeps the group's win rate near **80 %** for any `N` (ADR-0006 addendum
  2026-11-04).

Fight (resolved **instantly** when the lobby closes — no interaction is
possible, so no artificial pacing):

- Each participant fields **one random specimen** from their inventory. If it
  faints, that participant is out — no replacements.
- Per round: all living participant Pokemon attack the boss once, in
  seed-random order; then the boss attacks `⌈N / BossZieleTeiler⌉`
  (default 3) different random living participant Pokemon — all of them if
  fewer are alive. `N` is the participant count at the start.
- Boss HP reaches 0 → **every participant whose Pokemon is still alive
  catches the boss** (one new specimen each). No dice roll — survival is the
  catch condition.
- All participant Pokemon faint first → the boss escapes, nobody catches.
- Chat output: start message, result summary (who caught / boss escaped) and
  the battle-log link. The global cooldown (`BossCooldownMinutes`, default 30)
  starts when the encounter **ends**.
- When that cooldown runs out, the bot announces „Der Boss ist wieder bereit –
  schreibt !boss, um ihn zu rufen!“ (since 1.0.3). Not after the short
  retry cooldown of a failed lobby, not after `!bossreset` (it announces
  itself), not in the dry run, not while the bot takes no commands (§8), and
  not if the app was restarted during the cooldown (the timer is not stored).
- Achievement unlocks caused by the catches are announced afterwards:
  „X hat 15 verschiedene Pokémon gesammelt und kann jetzt Eich mit
  !challenge Eich herausfordern!"
- Joining is not confirmed per player (30 viewers would flood the chat).
  `!boss` during a cooldown answers „@Name, der nächste Boss kann in X Minuten
  gerufen werden." — at most every 30 s for the whole chat (WP-03 decision).
- Replies (final wording: [chat-texts.md](chat-texts.md)): lobby „Ein wilder Boss nähert sich!
  Schreibt !boss, um mitzukämpfen – noch 2 Minuten.“; start „Ein wildes
  Arkani (selten) erscheint! 5 Trainer kämpfen mit.“; result „Arkani wurde
  besiegt! Gefangen von: A, B.“ or „Arkani ist entkommen – alle Pokémon wurden
  besiegt. Arkani hatte noch 45 von 270 HP.“ (an escaped boss reports its HP
  left and at the start — streamer request 2026-11-08; the start value matters
  because boss HP grows with `N`; the fight page and the desktop list of fights
  show the same sentence, read from the log); too few see above. The result ends with the battle link
  (WP-06).
- Dry run: cooldowns are skipped so a test can be repeated at once; an open
  lobby is dropped when the dry run is switched.

## 5. Battle engine

Used by boss, PvP and NPC fights.

- **Damage:** `max(1, round(Skalierung × Quote × Typfaktor × Streuung × Krit))`
  - `Quote` = the better of physical and special (ADR-0006):
    `max((ATK_a + k) / (DEF_d + k), (SPEZ_a + k) / (SPEZ_d + k))` with
    `k` = `Daempfung` (default 50). As in Gen 1, Special serves as both
    special attack and special defense. The damping keeps outliers (Chaneira
    DEF 5, Onix DEF 160) from deciding fights on their own.
  - `Skalierung` default 20 (ADR-0006 addendum 2026-10-19)
  - `Streuung` uniform in [0.85, 1.00]
  - Crit: factor `KritFaktor` (default 2.0) with chance `KritChance`
    (default 6.25 %)
  - `Typfaktor` from the type chart: the better of the attacker's types,
    multiplied over the defender's types (see §2)
  - No STAB, no immunities. Minimum damage 1 makes stalemates impossible.
- Effective HP in any fight = base HP × `HPFaktor` (default 1.0). HP exists
  only inside a fight; everything is healed afterwards.
- **1-vs-1 turn rules (PvP/NPC):** the challenger strikes first. When a
  Pokemon faints, its side sends the next random team member and that side
  attacks first.
- `MaxRunden` (default 200) is a pure safety net — reaching it is a bug, is
  logged as a warning, and the side with the higher remaining HP sum wins.
- **Determinism:** the RNG is injected; every battle stores its seed. The
  full log is still persisted verbatim (replaying a seed after a balancing
  change would yield a different outcome, so logs are data, not derived).
- Log lines (German, owner and HP after the hit in brackets): `Runde 1` /
  `Pikachu (Ash, HP 35) hat Arkani (Boss, HP 120) 40 Schaden zugefügt.`
  plus ` Volltreffer!`, ` Sehr effektiv!` or ` Nicht sehr effektiv.` /
  `Arkani (Boss) wurde besiegt.` / `Misty schickt Karpador in den Kampf.`

## 6. PvP (`!fight`)

- `!fight @name` challenges another registered trainer. Requirements: both
  own **≥ 6 specimens**; neither has another open challenge (one open
  challenge per trainer, in either direction).
- The challenged trainer accepts with `!fight @challenger` within
  `HerausforderungTimeoutMinutes` (default 2); otherwise the challenge
  expires silently.
- Teams: **6 random specimens per side**, drawn by the engine. The starter
  may be drawn like any other specimen.
- Reward: the winner receives **one random specimen from the loser's team of
  6, excluding the starter specimen** (pool may thus be 5). The transfer is
  permanent; only that concrete specimen is protected — further copies of the
  starter's species are normal loot.
- No cooldown between trainer pairs (v1; revisit if trading-by-losing gets
  abused).
- A trainer may be in a boss lobby and a PvP fight at the same time —
  inventories are only touched when a fight resolves.
- The PDF's original challenge mode (show team, opponent hand-picks a team,
  winner picks the reward) is **deferred to a later version**.
- `@name` is matched case-insensitively against the trainer's Twitch login,
  then against the display name (both refreshed whenever the trainer writes in
  chat; WP-04).
- Open challenges live in memory: a restart or switching the dry run drops
  them. Requirements are checked again when the challenge is accepted.
- Achievements reached through loot are announced like boss catches.
- Replies (WP-04, wording accepted in WP-08, `docs/chat-texts.md`): challenge „@Misty, Ash fordert dich
  zum Kampf heraus! Nimm an mit !fight @ash – du hast 2 Minuten.“; result
  „Ash besiegt Misty und bekommt Karpador von Misty!“; on accept with too few
  specimens „Der Kampf fällt aus: Ash hat erst 5 Pokémon – …“; rejections:
  no name („fordere jemanden zum Kampf heraus – zum Beispiel: !fight @Name“),
  unknown name („gary ist noch kein Trainer.“), oneself („du kannst dich nicht
  selbst herausfordern.“), too few specimens („du hast erst 3 Pokémon – für
  einen Kampf braucht ihr beide mindestens 6.“), an open challenge on either
  side („du hast schon eine offene Herausforderung.“ / „Misty hat schon eine
  offene Herausforderung.“). With the website set up, the result carries the
  link to the fight page (§9).

- Player side: 6 random specimens, same rules and minimum (≥ 6) as PvP. The
  player is the challenger and strikes first.
- NPC side: the fixed team above; stats = base values × per-NPC strength
  multiplier (`npcs.json`, configurable per NPC).
- Cooldowns per trainer and NPC, both configurable: after a **loss**
  `NPCNiederlageCooldownHours` (default 48), after a **win**
  `NPCSiegCooldownMinutes` (default 60) — the win cooldown exists to limit
  farming.
- Error replies (WP-08 wording): „@Name, gegen Eich kannst du in 46 Stunden
  30 Minuten wieder antreten." / „@Name, für Eich brauchst du noch 13
  verschiedene Pokémon."
- Reward (E22, user decisions 2026-10-21): only the **first win** against an
  NPC brings a reward —
  - its badge,
  - its tokens, staggered per NPC (`tokens` in `npcs.json`; default rising
    with the threshold: Eich 1 … Ash 17),
  - one specimen of the NPC's team: a random species the trainer does not own
    yet, or a random team species if they own all six. It counts for
    achievements like a catch.

  Further wins and losses bring nothing; NPCs can still be fought again.
- Replies (`docs/chat-texts.md`): „Ash besiegt Eich und bekommt den Orden von Eich,
  Glumanda und 1 Token!“ (first win) / „Ash besiegt Eich erneut – eine
  Belohnung gibt es nur beim ersten Sieg.“ / „Eich besiegt Ash! Nächster
  Versuch in 48 Stunden.“; without or with an unknown name the bot lists the
  unlocked NPCs.
- In the dry run the cooldowns are skipped, as for the boss.

## 8. Commands

| Command                    | Who        | Effect                                        |
|----------------------------|------------|-----------------------------------------------|
| `!registrieren <Starter>`  | anyone     | one-time registration with starter            |
| `!boss`                    | registered | open boss lobby / join during countdown       |
| `!fight @name`             | registered | challenge (or accept a pending challenge)     |
| `!challenge <NPC>`         | registered | fight an unlocked NPC                         |
| `!arena`                   | anyone     | posts the website link                        |
| `!pokearena`, `!version`   | anyone     | status check: „PokeArena-Bot ist online (Version x).“ |
| `!bossreset`               | mods       | reset the global boss cooldown                |
| `!entfernen @name`         | mods       | delete a trainer (see §11)                    |

All other management (config values, token setup, manual corrections, backup)
lives in the WPF UI, not in chat. Pokemon names in commands are matched
case-insensitively against `name` and `slug`.

Commands count only while the channel is **live** (§12). Offline, a known
command gets „PokeArena läuft nur, solange der Stream live ist. Bis zum
nächsten Stream!“ — at most once every 5 minutes for the whole chat; unknown
commands stay silent as always. Fights already under way (a running boss
countdown, an open challenge) finish normally. The streamer can switch on
„Auch ohne Stream“ in the desktop app to test offline; the
switch is not stored and is off after every app start. The dry run is never
gated.

Error and hint replies to one viewer (unknown name, too few Pokémon, NPC
cooldown, not registered …) go out at most once per viewer, command and 30
seconds (not in the dry run); further ones in that time are dropped, so a viewer spamming commands cannot
delay fight results (review 1.0.3). Names typed by a viewer are repeated in a
reply only if they are a plain name (letters, digits, „_“, at most 25
characters); otherwise the reply says „diesen Trainer / NPC“. Arguments are
split at any whitespace. `!challenge @Eich` works like `!challenge Eich`.

## 9. Website

The site is split into an app and its data:

- **App:** static **Blazor WebAssembly**, hosted on **GitHub Pages** in this
  repository under its own subdomain, deployed by a GitHub Actions workflow.
  It is rebuilt only on code changes and contains **no player data**.
- **Data:** JSON files in a **Cloudflare R2** bucket, publicly readable via a
  **custom domain** with Cloudflare's cache and a rate-limiting rule in front;
  `r2.dev` stays off (ADR-0003 addendum). The data base URL is a config value
  of the web app. CORS allows `GET` from the site's origin. The bot uploads
  through the S3-compatible API with an R2 API token scoped to this bucket
  (`Object Read & Write`), stored in the Windows credential store.

Rationale: no deploy per data change (uploads are live in seconds), no commit
noise in the code repository, and deletions are real — a public git history
would keep deleted trainers' names forever (see §11).

Pages (v1): leaderboard, list of fights, battle log per fight, trainer detail
page, privacy note, player guide („So geht's“, `/anleitung`). The OBS overlay
is served by the desktop app, not by the website (below).

The player guide is static text: it repeats the defaults of §13 (countdown,
minimum team size, cooldowns) and the NPC thresholds of §7, because the site
has no access to the bot's configuration or base data. A release that
changes one of them updates `Pages/Guide.razor` as well.

Data files (all derived — fully regenerable from the DB; the UI has a
"republish everything" action):

| File                       | Content                                              |
|----------------------------|------------------------------------------------------|
| `rangliste.json`           | rank, display name, distinct count, total count, player count, timestamp. Sort: distinct desc, then total desc, then earliest attainment¹ |
| `trainer/<twitch-id>.json` | pokedex (species + count), achievements, recent fights, stats |
| `kampf/<id>.json`          | participants, teams, log lines, result, loot, seed   |
| `kaempfe.json`             | last N fights for an index page                      |
| `meta.json`                | data format version, timestamp                       |

¹ Attainment = the moment the trainer last completed the set of species they
own now: for each owned species the earliest time they got a specimen of it
that they still hold (caught or won), and of those the latest. Losing a
species and regaining it moves the moment to the regain (WP-06 decision).

- Files are uploaded **directly per change** via the publish queue.
- Uploads normally land within seconds, but the queue may lag (network
  failure, bot offline). The battle page therefore shows a friendly
  „Kampf wird gerade veröffentlicht …" state and retries while the JSON
  404s, so links posted to chat immediately are never broken.
- Caching: `kampf/<id>.json` changes only when a trainer in it is deleted
  (§11), so it gets `max-age=86400` — a deleted name drops out of every cache
  within a day without a purge (WP-08 decision);
  all other files are mutable and uploaded with a short max-age (≤ the poll
  interval) so browsers and the Cloudflare cache never serve stale
  leaderboards.
- The leaderboard and the list of fights poll every 15 s; a fight page
  retries a missing file for 2 minutes (a chat link can be faster than the
  upload), then says the fight is not there yet. The OBS overlay is not part
  of the website: the desktop app serves it locally and it polls every 2 s.
- Trainer URLs use the Twitch user id as filename; friendly routes resolve
  names via the leaderboard data.
- **OBS overlay:** OBS runs on the same machine as the bot, so the overlay
  browser source points at a **local Kestrel endpoint of the WPF app**
  (instant updates, works offline). The public site keeps the polled
  snapshots.

## 10. Storage

- **SQLite (EF Core) is the single source of truth**: trainers, specimens,
  fights (including full logs and seeds), achievements, NPC badges, token
  balances, cooldowns and the publish queue. Balancing values are code
  defaults (§13), not data. Loot transfers run in one transaction. Open PvP
  challenges and the boss lobby are short-lived and stay in memory.
- A **publish queue** (outbox) decouples game logic from uploads; network
  failures lose nothing.
- **Secrets** (Twitch tokens for the dedicated bot account, R2 API token) go
  into the Windows credential store — never into the DB, config files or the
  repo. The UI shows the signed-in bot account (ADR-0002 addendum).
- **Backup:** a `VACUUM INTO` copy on every app start, before the migrations,
  plus a manual „Jetzt sichern“ button; the newest 10 are kept in
  `%LOCALAPPDATA%\PokeArena\backups` (WP-08 decision). Restoring is manual.
- **Dry run:** game data goes to an in-memory sandbox database that starts
  empty each time the dry run is switched on; real chat messages are not
  processed meanwhile.

## 11. Privacy

Display names appear permanently on a public website. Therefore:

- `!entfernen @name` (mods) and a UI action delete a trainer and their
  specimens, delete their `trainer/<twitch-id>.json` from the bucket, and
  republish affected files; the trainer's name in existing battle logs is
  replaced by „[gelöscht]". Because player data never enters the git
  repository, nothing survives in any history.
- A short privacy note lives on the website.

## 12. Twitch integration

- Transport: **EventSub WebSocket** (`channel.chat.message`) for reading,
  **Helix Send Chat Message** for writing. No IRC.
- Auth: **Device Code Flow** (public client, no secret) for the dedicated
  bot account; scopes `user:read:chat`, `user:write:chat`, `user:bot`. With
  this user token neither `channel:bot` nor moderator status is required
  (ADR-0002 addendum); the streamer still makes the bot a moderator, which
  protects its replies against slow mode. The sender keeps the normal-user
  limits either way. A login with the channel's own account is refused.
- Outgoing messages run through a rate limiter with a queue; results of mass
  events (boss) are aggregated into few messages and respect the 500-char
  message limit.
- Live status (WP-07): EventSub `stream.online` / `stream.offline` on the
  same session (no extra scope). Events only report changes, so the bot asks
  Helix `GET /streams` for the current state on every new session, every
  2 minutes for the first 10 minutes while it says offline, and once an hour;
  unknown counts as offline. Helix lags a few minutes, so its answer never
  overrides a stream event of the last 10 minutes (review 1.0.3).
