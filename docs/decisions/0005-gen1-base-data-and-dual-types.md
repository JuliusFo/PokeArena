# ADR-0005: Gen-1 base data and dual types

Status: accepted · Date: 2026-10-11 · Changes spec §1, §2, §5 (previously:
exactly one type per species, values supplied by the owner)

## Context

`data/pokemon.json` was an open point blocking WP-03. Official values exist,
but differ by generation: Gen 2 split Special into two stats, Gen 6 buffed
several species, and some types changed (Piepi/Pummeluff became Fairy,
Magnetilo Electric/Steel) — types the Gen-1 chart does not have. The spec
allowed one type per species, but with "first type only" no Gen-1 Pokemon
would be Flying (it is never the first type in Gen 1).

User decisions on 2026-10-11:

- Use the official values of **Generation I**.
- Keep **real dual types** instead of reducing to one.
- A dual-type attacker uses the **better** of its two types.
- Rarity comes from a rule, then a manual review.

## Decision

- `data/pokemon.json` is generated by `tools/GeneratePokemonData.cs` from
  PokeAPI (`past_stats` / `past_types` give the Gen-1 values). Fields: `hp`,
  `atk`, `def`, `spez` (Gen-1 Special), `typen` (1–2). The generated file is
  committed; the script makes it reproducible.
- Verified on 2026-10-11: HP/ATK/DEF/Special of all 151 match Bulbapedia's
  Generation I table.
- Type factor: multiply the chart factors over the defender's types; for a
  dual-type attacker take the maximum over its types.
- Rarity rule (in the script): legendary = Arktos, Zapdos, Lavados, Mewtu,
  Mew; rare = Gen-1 stat total ≥ 425 or rare in the original games (starter
  lines, Pikachu/Raichu, Evoli line, fossils, Dratini line, one-of-a-kind
  encounters); everything else common. Result: 98 / 48 / 5.

Deliberately **not**: modern stats or types, Speed (no use in the engine),
moves.

## Consequences

- Flying, Ice, Ghost and Dragon types now appear in play.
- Factors reach 4× and 0.0625×; minimum damage 1 still prevents stalemates.
- Official stats include extreme outliers (Chaneira DEF 5, Onix DEF 160,
  Karpador ATK 10) — the damage formula question in WP-03 becomes concrete.
  `spez` is available should the formula use it.
- Manual edits to `seltenheit` are lost on regeneration unless the rule in
  the script is changed instead; edit the script, not the JSON.
